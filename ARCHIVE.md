# Archive

State of the project's artifacts as of 2026-09-16, when it was wound down.

`data` is in `.gitignore`, so git carries no record of the 443 GB this project
produced. This file plus `archive/` is that record. It exists so that the
checkpoints and caches deleted here can be told apart from the ones that were
lost, and so that anything still needed can be either found or rebuilt.

Off-machine copy: `onedrive:/Project/AdvScene/`. There is no second local disk;
`/home` is the only other copy.

## What is on OneDrive, and why some of it is tarred

```
onedrive:/Project/AdvScene/
  data/final/<model>/last.ckpt     the 35 checkpoints, loose and individually fetchable
  data/final/{scene_gen,table_main,table_main_valid,planners}/   the tables, loose
  tarballs/data_final_cache.tar.zst          100 564 files -> 549 M
  tarballs/data_final_test.tar.zst             2 542 files -> 501 M
  tarballs/data_final_scenecontrol.tar.zst     2 034 files ->  20 M
  tarballs/data_final_backups.tar.zst            281 files ->  11 M
  tarballs/critical_scene_artifacts.tar.zst   29 491 entries -> 10 G
  tarballs/wandb.tar.zst                       1 624 entries -> 384 M
  checkpoints/planners/, metadata/, temp/, archive/, ARCHIVE.md, AGENTS.md
```

The trees with many small files are tarred because they cannot be uploaded file
by file in reasonable time: measured against this OneDrive remote, rclone
sustains about **2.9 files/s** regardless of file size, which puts
`data/final/cache` alone (100 564 pickles, 3.2 G) at roughly 10 hours. As
`.tar.zst` it is 549 M and uploads in under a minute. The checkpoints stay loose
because they are large, bandwidth-bound, and are the thing you would want to
fetch one of.

Restore with `zstd -dc <file>.tar.zst | tar -xf - -C data/` (the tars are rooted
at `cache/`, `critical_scene/` and so on). `critical_scene_artifacts.tar.zst`
holds 79 symlinks with absolute paths into
`/home/tjhu78u/workspace/scenario-dreamer/data/critical_scene/`; they resolve
only if restored to that same path.

## Checkpoint provenance

`archive/MANIFEST.json` (and `MANIFEST.sha256` beside it) is generated by
`scripts/archive_manifest.py`, never written by hand. For each of the 35
checkpoints it records the SHA256, the byte count, and what the file says about
its own training run.

A DDPO checkpoint carries a `ddpo` block: the iteration it stopped at, the KL
coefficient in force, the base checkpoint it started from, and the **wandb run
id**, which is what connects a weight file back to its training curves in
`wandb/`. All 32 RL checkpoints name the same base:
`data/checkpoints/advscene_ldm_adv_base/last.ckpt`, archived as
`data/final/advscene_base_ldm/last.ckpt` and verified identical to it.

| Group | n | Iteration | Backs |
| --- | ---: | ---: | --- |
| `advscene_rl_main/` | 12 | 500 | the paper's main table, one per SUT x traffic cell |
| `advscene_rl_v4_batch/` | 12 | 500 | the reward-series v4 row in AGENTS.md (default KL) |
| `advscene_rl_ablation_kl/` | 5 | **1000** | the KL sweep |
| `advscene_rl_ablation_reward/` | 2 | 500 | the `noprox` / `nottc` leave-one-out arms |
| `advscene_rl_ablation_nokl/` | 1 | 700 | "removing the trust region destroys the generator" |
| base / baseline | 3 | -- | `advscene_base_ae`, `advscene_base_ldm`, `scenario-dreamer` |

Two things the manifest settles that the prose did not:

- **`last.ckpt` is a strict superset of `_00500.ckpt`.** AGENTS.md's evaluation
  protocol names `_00500.ckpt`, while what was archived is `last.ckpt`. Measured
  on `ppo-ppo_norm_v4kl5`: the two `state_dict`s differ in **0 of 197 tensors**,
  and `last.ckpt` additionally carries the `ddpo` block. Archiving `last.ckpt`
  therefore loses nothing and gains the provenance. The KL-sweep runs are the
  exception to the protocol in a different way: they ran to iteration 1000, not
  500.
- **The ScenarioDreamer baseline checkpoint is at step 148 356, not 150 000.**
  The run was configured `max_steps=150000` and its log reports reaching it, but
  `ModelCheckpoint` saves per epoch, so `last.ckpt` holds the end of epoch 77.
  The 1.1% gap is benign; it is recorded because "trained for exactly 150k steps"
  describes the run, not the file.

## What was deleted, and why

All of it was DDPO checkpoints under `data/critical_scene/`. No scene artifact,
summary, provenance record or figure was removed. The full per-file lists,
with sizes, mtimes, run names and iteration numbers, are in `archive/`.

| Tier | Files | Freed | Record |
| --- | ---: | ---: | --- |
| `hier_v2`, `v2_no_prior`, `v3` weights | 181 | 140.4 GiB | `archive/deleted_tier1_void_v2_v3.json` |
| `hier_v4*` weights | 85 | 67.6 GiB | `archive/deleted_tier2_superseded_v4.json` |
| dangling git blob | 1 | 11.4 GiB | none needed -- see below |

**Tier 1 (v2 / v3) was deleted without archiving, deliberately.** AGENTS.md
declares both VOID: they were trained before the 2026-09-04 sim boundary
(control-every-agent, plus PDM lateral offsets), so they optimised a different
simulator, and AGENTS.md further states that settling whether a fault-agnostic
collision band beats v4 needs v3 **retrained** under the current sim rather than
re-scored. An archived v3 weight could not produce a valid number. What those
rows actually rest on -- the already-scored artifacts in `table_main_v3/`,
`rescore_face_20260907/` and `table_main_20260830/` -- is kept.

**Tier 2 (v4) was archived first.** Every v4 run's final weights are in
`data/final/`, byte-identical to the deleted source and verified by SHA256
before anything was removed; 13 of them (`advscene_rl_v4_batch/`,
`advscene_rl_ablation_nokl/`) were copied in during this pass, because AGENTS.md
reports findings from those runs and only the other 19 had been curated.

**The git blob** was a 13.07 GB unreachable object left by a `git add` of
`data/checkpoints/scenario_dreamer_ldm_large_waymo/last.ckpt` on 2026-07-29. It
was unreferenced by every ref, every reflog and `git fsck`, and the checkpoint
itself is still on disk. `git gc --prune=now` took `.git` from 13 G to 1.6 G, of
which 65 M is the real history and 1.5 G is the `gpudrive` submodule clone.

| a v4 per-iteration snapshot | not reproducible without a rerun, and not needed: the run's final weights are in `data/final/`. |
| `data/advscene_ae_goal_latents_waymo/` (19 G) | re-export from `data/final/advscene_base_ae/last.ckpt` + `data/advscene_preprocess_waymo/`. |

| `metadata/initial_prob_matrix_goal_waymo.pt` | `python scripts/create_goal_init_prob_matrix.py` |
| a context prior | `python scripts/headroom_probe.py`, 1024 contexts x 32 samples, 16 workers. Valid only for the exact `sut/env/adv` trio it was probed with. |

## Files that no git history holds

`.gitignore` excludes `*.pt`, `*.pkl`, `data`, `temp/` and `research/`, so these
are carried by the disk and the OneDrive copy alone. They were uploaded for that
reason; none of them is recoverable from a clone.

- `checkpoints/planners/**` -- all 13 planner weights. Three are Hydra defaults
  (`ppo_normal`, `ppo_aggressive`, `ppo_caution`) and break every rollout if
  lost. The seven `smart/` weights are the odd ones out: they are **not**
  mirrored into `data/final/planners/`, which carries only the six cond_drive /
  ppo / selfplay files. SMART was a negative result, but those weights are the
  only evidence of it.
- `metadata/initial_prob_matrix_goal_waymo.pt`, `metadata/waymo_goal_val_eval_set.pkl`
  -- gitignored by `*.pt` / `*.pkl`, yet Hydra defaults in four configs.
  Regenerable, but only while `data/advscene_preprocess_waymo/` survives.
- `temp/` -- per AGENTS.md this holds the current scene-gen tables.
- `research/` -- gitignored here. `research/overleaf/` is its own git repo with
  an Overleaf remote, so it is covered by that remote. **`research/results/` has
  a `.gitignore` of `*` and is in no git history at all**, and unlike the entries
  above it was not uploaded. It is the one real gap left.

## Verifying the archive

```bash
python scripts/archive_manifest.py --verify        # re-hash all 35 checkpoints
rclone check data/final onedrive:/Project/AdvScene/data/final --one-way
rclone check data/final onedrive:/Project/AdvScene/data/final --one-way --download \
    --include 'advscene_rl_main/**'                # content compare, costs a download
```

The local check is the authoritative one: it is a full SHA256 against
`archive/MANIFEST.json`, and it is what gated the deletions. The remote check is
weaker than it looks -- this OneDrive remote returns no usable hash to rclone
1.60 (`hash unsupported` for both quickxor and sha1), so a plain `rclone check`
compares size and modification time only and reports "hashes could not be
checked". `--download` is the way to compare content, at the cost of pulling the
bytes back.

`SCRATCH_ROOT` and `DATASET_ROOT` are set to the relative path `data` by
`scripts/define_env_variables.sh`, so every `${scratch_root}/...` in `cfgs/`
means `<repo>/data/...`. Restoring the archive somewhere else needs a symlink at
`<repo>/data` or an edit to that script.
